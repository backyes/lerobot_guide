# 调试舵机实战 Tutorial

> 基于真实硬件调试经验，从零开始完成串口舵机的扫描、改ID、中位校准。

## 环境准备

### 硬件清单

| 设备 | 说明 |
|------|------|
| FT 舵机 (HLS 系列) | 型号 0903，协议 FT-SCS |
| CH343P USB 转串口 | VID:PID = 0x1A86:0x55D3 |
| 独立电源 | 6V-7.4V（USB 带不动舵机！） |
| 杜宾线 | TX→SIG，共地 |

### 软件安装

```bash
git clone https://github.com/backyes/lerobot_guide.git
cd lerobot_guide
pip install -r requirements.txt
```

## Step 1: 扫描总线

首先确认硬件连接正常，扫描所有在线的舵机：

```bash
python -m core scan --port /dev/cu.usbmodem5B790502931
```

预期输出：

```
╭─────────────────────────────────────────╮
│ 🔌 连接信息                             │
├──────────┬──────────────────────────────┤
│ 端口     │ /dev/cu.usbmodem5B790502931  │
│ 波特率   │ 1,000,000 bps                │
│ USB 芯片 │ CH343P                       │
│ VID:PID  │ 0x1A86:0x55D3                │
│ 协议     │ FT-SCS                       │
╰─────────────────────────────────────────╯

==================== 🔍 扫描舵机 ====================

  ✅ ID=  1  型号=0x0903  位置=2640

共找到 1 个舵机: [1]
```

**关键信息：**
- `0x0903` = HLS 系列舵机
- `位置=2640` ≈ 773°（原始值 × 0.087°）

## Step 3: 修改 ID（串接多舵机时）

当总线上有多个舵机时，出厂默认都是 ID=1，会冲突。需要逐个修改：

**操作：** 只保留目标舵机连接，其余断开：

```bash
python -m core set-id --port /dev/cu.usbmodem5B790502931 --old 1 --new 2
```

预期输出：

```
==================== 🆔 修改舵机 ID ====================
  从 1 改为 2
  ✅ 成功（断电后生效）
```

**⚠️ 重要：** 修改后断电重启，新 ID 才会永久保存。

## 常见问题

### 扫描不到舵机

| 排查项 | 检查方法 |
|--------|---------|
| 供电 | 万用表测量舵机电源脚是否有 5-7V |
| 共地 | 确保 USB 模块 GND 与舵机 GND 相连 |
| 信号线 | TX 接舵机 SIG（不是 RX） |
| 波特率 | 尝试 `--baud 115200` |

### 修改 ID 后不生效

- 必须断电重启
- 锁定要用**新 ID** 发：`write_byte(new_id, Lock, 1)`

### 校准后位置还是不对

- HLS 系列校准是写 128 到**扭矩开关寄存器**，不是写偏移量
- 校准后检查偏移寄存器是否更新（0 → 非零）

### 返回数据全是 0

- 某些型号不支持电压/温度检测
- 忽略即可，不影响核心功能

## 进阶：使用 -v 查看通信帧

加 `--verbose` 可以看到原始通信数据：

```bash
python -m core scan --port /dev/cu.usbmodem5B790502931 -v
```

输出包含每帧的 hex dump 和字段解析：

```

│  指令       01 (Ping)                     │
```
